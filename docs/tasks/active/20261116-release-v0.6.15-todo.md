# Release v0.6.15

**Created**: 2026-11-16

Cut `v0.6.15`, urgently. The frontend ships on every `main` merge, so
production already runs #1141's Trash UI ("Move to Trash … where you can
restore them") against the `v0.6.14` backend, where `DELETE /documents/:id`
is still a **permanent delete** and the trash routes do not exist
(`GET /workspaces/:wid/trash` and `POST /documents/:id/restore` answer `404`
unauthenticated, while existing guarded routes answer `401`; checked
2026-11-16). Until this backend is live, a document a user moves to Trash is
gone. The rest of the window rides along.

## Preconditions

- [x] **Production Yorkie is at least v0.7.28.** The SDK bump (#1166) pairs
      with it, and the demo daily reset (#1148) needs yorkie#2365.
      `kubectl -n yorkie get deploy` reports `yorkieteam/yorkie:0.7.28`, 3/3
      ready (checked 2026-11-16). The stale unique label index
      `revisions.doc_id_1_project_id_1_label_1` (from yorkie#1582) was dropped
      on production MongoDB the same day; history-panel Restore verified.
- [x] **The new migration is additive.**
      `20261114064942_document_trash` adds a nullable `Document.deletedAt`
      and an index on `(workspaceId, deletedAt)`; the `prisma-migrate` init
      container applies it on rollout. Existing rows stay live (`NULL`).
- [ ] **Frontend/backend skew.** Not "none" this time: the frontend is
      already ahead (above). Rolling the backend forward closes it; there is
      nothing to hold back.
