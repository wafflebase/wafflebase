# Release v0.6.20

**Created**: 2026-11-28

Cut `v0.6.20`, which ships workspace bots (#1213), and bring the backend up
to what the frontend already serves. GitHub Pages deploys `main`, so
wafflebase.io has been showing Settings → Bots since #1213 merged, against
a `v0.6.19` backend that has none of its routes.

Probed read-only on 2026-11-28: `GET https://api.wafflebase.io/workspaces/x/bots`
→ `404` (route absent; an existing route such as
`/workspaces/x/chat/channels` → `401`), `/health` → `200`.

## Preconditions

- [x] **One Prisma migration, applied by the init container.**
      `20261128000000_workspace_bots` (#1213), run by the `prisma-migrate`
      init container (`npx prisma@6 migrate deploy`) before the server
      starts. Additive only:
  - `User` gains `kind TEXT NOT NULL DEFAULT 'person'` and four nullable
    `bot*` columns. A constant default is a catalog-only change on
    Postgres 11+, so the `User` table is not rewritten.
  - `ChatMessage` gains nullable `agentTaskId`.
  - New tables `BotPairingCode` and `AgentTask`, both empty at apply time.
  - New indexes on the new tables, on `ChatMessage(agentTaskId)` (every
    value `NULL`) and `User(botWorkspaceId)`; FKs with `SET NULL` /
    `CASCADE`. Nothing drops, rewrites or backfills.
- [x] **No setting production must add.** #1213 adds no environment
      variable; bots ride the existing chat bus (`LISTEN agent_task` on the
      shared `PgBus`, falling back to a poll when it is down) and the
      existing API-key machinery.
- [x] **New routes, frontend already ahead.** Nothing removed or changed
      incompatibly; a cached old frontend keeps working.
  - `GET` / `POST /workspaces/:wid/bots`, `DELETE …/bots/:botId`,
    `POST …/bots/:botId/pairing-codes`
  - `POST /auth/pair` (unauthenticated, throttled 10/min)
  - `GET /api/v1/workspaces/:wid/agent/tasks/next`,
    `GET …/:taskId/thread`, `POST …/:taskId/reply`,
    `POST …/:taskId/complete` (bot keys only)
  - `GET /workspaces/:wid/members/:userId/removal-impact` gains
    `botsRemoved`; an older frontend ignores it.
- [x] **Sign-in paths refuse bot accounts** (#1213): OAuth
      (`?error=bot_account`), `cli/exchange`, desktop session and refresh.
      No existing user has `kind = 'bot'`, so nobody is affected.
- [x] **CLI and plugin.** `@wafflebase/cli` 0.6.20 adds `bots` / `agent`
      commands, `status.auth`, the `ctx switch` override warning and a
      non-interactive `login`; the plugin adds `/wafflebase:listen`. The
      plugin's safety table is regenerated for 0.6.20.
- [x] **Desktop.** `packages/desktop` and `Cargo.toml` / `Cargo.lock` bump
      with everything else; `desktop-release.yml` runs unattended on
      `release: published` (#1209). The only desktop code change is
      #1211's test fix.
