# Release v0.6.7

Bump the Yorkie SDK to its latest release and close out v0.6.7 over the
`v0.6.6..HEAD` window (26 commits, 6 authors). Theme: **the docs editor
gains the surfaces a word processor is expected to have, a disconnected
editor stops looking like a connected one, and the agent development
loop gets its map**.

**Patch (not minor) bump.** The window adds no new document type and no
new package. Its largest items extend surfaces that already exist — docs
page setup and format painter (#985), v1 row/column endpoints (#986), the
sync-status chip (#967). Patch, consistent with v0.6.5 and v0.6.6.

## Yorkie SDK 0.7.17 -> 0.7.18

Four pins across three packages: `@yorkie-js/sdk` in frontend, backend
and notes, plus `@yorkie-js/react` in frontend. All four move together —
the React binding wraps the SDK and shares its version line.

0.7.18 is a fixes-only release, and three of the four land on paths
wafflebase actually exercises:

- **Anchor `RGATreeList.insert` on the last node's position identity**
  (yorkie-js-sdk#1332). The array CRDT under every slide list, element
  list and axis array.
- **Recover style ranges collapsed by a merge at the `from` anchor**
  (#1329). Tree styles — the docs inline-style path.
- **Relink the insertion chain when restore recreates a purged fragment**
  (#1328). The restore path undo rides.
- **Reject integers outside the int64 range** (#1326).

No server-image pin to move: `docker-compose.yaml` and `ci.yml` both
track `yorkieteam/yorkie:latest`.

## Highlights

### Product — Docs

- **Page setup, markdown/plain-text export and the format painter reach
  the UI** (#985). Four capabilities were already complete in the engine
  with no way to open them — `PageSetup`/`store.setPageSetup` had zero
  UI, and `serializeMarkdown`/`serialize/text.ts` were consumed only by
  the CLI. The behaviour did not change; the door did.
- **The four loose ends #985's review filed are closed** (#992). All
  four pre-existing, which is why they were filed rather than folded in.
  The sharpest: the PDF link-annotation writer validated `new URL(href)`
  and then wrote the *raw* `href`, so the string that cleared the
  protocol allowlist was not the string in the file — and since
  `PDFString.of` escapes nothing, an unbalanced `)` closed the literal
  and `>>` closed the action dictionary, producing a PDF that failed to
  parse at all.
- **A `batch()` seam on `DocStore`**, with named-style updates folded
  into one undo unit (#983).
- **Table-cell content and click-selected images copy with their
  formatting** (#984).
- Image tinting is confined to the image the selection actually covers
  (#982) — previously a selection spanning one image tinted others.

### Product — Sheets

- **Axis-ID coverage is bounded** (#980), so a selection far outside the
  populated grid stays fast instead of materializing every axis entry up
  to it.

### Product — Notes

- **Blockquoted lists** are handled by the list commands (#977).
- **`<img>` sizing** is supported in the preview through a narrow
  attribute allowlist (#975).
- The toolbar fits on a phone (#981).

### Sharing

- **Shared-link images are tokenized in notes and sheets too** (#993),
  extending the v0.6.6 fix (#955) that covered slides and board. The
  resolver map is now keyed on the four types that render
  workspace-scoped images; `doc` is genuinely unaffected because it
  uploads through the legacy unauthenticated `/images` route, so it was
  never gated to begin with. That closes the class — an anonymous
  share-link viewer sees the images in any document type — though by two
  different mechanisms rather than one.

  One limit worth carrying, from #993's own Known limitations: the
  **sheets** half is covered by unit tests and inspection of both call
  sites, not by an end-to-end run — no shared sheet containing images was
  available to test against. The notes half *was* verified end to end
  (8 of 8 images, every `src` tokened, 403 without a token and 200 with
  one), and the mechanism is identical.

### Collaboration

- **A disconnected editor no longer looks like a connected one** (#967):
  a four-state chip (`Saved` / `Saving…` / `Reconnecting…` / `Not saved`)
  in `SiteHeader`, a transition toast, and a `beforeunload` guard.
  Design: `docs/design/sync-status.md`, which targeted 0.6.7 and lands
  here.

### REST API v1

- **Row/column insert, delete and move** (#986) — structural edits over
  the API, running the same `applyWorksheetShift` / `applyWorksheetMove`
  the editor does, so formulas, merges, styles, validations, anchors,
  comment threads and index-keyed view state all follow the edit,
  cross-tab pass included. It also **moves the worksheet axis/structure
  code out of the frontend into `@wafflebase/sheets`** — it was already
  pure engine code that the backend simply could not reach — and shares
  `normalizeStoredCell` so both stores agree on a stored cell's shape.
- **Remaining deep worksheet features** (#974): conditional formats,
  data validations, filter/pivot, range and sheet styles, column/row
  styles and widths/heights, charts, and a `clear-range` that empties a
  range while keeping structure. `GET` returns plain JSON — a Yorkie
  value's `toJSON` would otherwise double-encode, the same trap #958 hit
  on cell styles last release.

### Fonts

- **Font previews are subset to the glyphs each row paints** (#969),
  building on the lazy row loading v0.6.6 shipped (#947).

### Developer tooling — design editor

- **The loop opens end to end** (#964): one command in, a pull request
  out. Plus a defect report from inside a scene frame (#972), an
  installed copy of the package that works (#966), a missing git identity
  reported instead of a stack trace (#971), and **`pnpm design` booting
  on a fresh clone** (#976) — `packages/core/dist` is gitignored with no
  `prepare` script, so a clean checkout had none of it and every scene
  failed to resolve `@wafflebase/core/tokens.css`, reported as something
  else entirely.
- What running it taught is recorded (#962).

### Agent / review pipeline (dev infrastructure)

- **A map of the agent development loop** (#976) —
  `docs/design/agentic-dev-loop.md`, the start-here doc for the five ways
  work enters and the one back half they share.
- Four lens severities are graded by consequence rather than by kind
  (#970); deferred findings get an advisory check run (#965); the promote
  job's exit-code chain is closed and its gates hardened (#968); the
  eval harness gets an operator's guide (#978).

### Homepage

- Demo tabs stay on one line on phones (#979).

## Decisions taken at cut time

- **The Yorkie SDK bump rides the release PR** rather than going in
  ahead of it. v0.6.5 made the opposite call for #919, merging the bump
  separately so it read as its own step. The reason to fold it in here
  is that 0.7.18 carries no feature and no API change — four upstream
  fixes on paths we already exercise — so it has nothing to say in the
  release notes on its own, and separating it would cost a second
  round of `verify:fast` on the same tree.
- **Patch, not minor.** No new document type and no new package. The
  standing convention reserves a minor for a new document type; the
  window's largest item (#985, docs page setup + text exports + format
  painter) extends a surface that already exists.
- **v0.6.6's task doc stays in `active/`.** Its last box — pin the
  backend image in `yorkie-team/devops` — is still open, and it is the
  only written record that the deployment does not carry v0.6.6.
  Archiving it would delete that record. v0.6.7's equivalent box will
  need the same access, which the release session has not had for two
  releases running.
