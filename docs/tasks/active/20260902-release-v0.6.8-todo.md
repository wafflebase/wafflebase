# Release v0.6.8

Close out v0.6.8 over the `v0.6.7..HEAD` window (8 commits, 2 authors).
Theme: **a document can be published as a template and reused by someone
else, the CLI stops being a fraction of the API it fronts, and Parquet
imports without a server round-trip**.

**Patch (not minor) bump.** The window adds no new document type and no
new package. Its largest item — the template gallery (#1000, #1001) —
adds a sidecar table and a set of routes around the copy engine that
already existed; the standing convention reserves a minor for a new
document type. Patch, consistent with v0.6.5, v0.6.6 and v0.6.7.

## No Yorkie SDK bump this release

`@yorkie-js/sdk` and `@yorkie-js/react` are pinned at `0.7.18` across
frontend, backend and notes, and `0.7.18` is still the published
`latest` on both. v0.6.7 moved them; there is nothing to move here.
`docker-compose.yaml` and `ci.yml` both track `yorkieteam/yorkie:latest`,
so there is no server-image pin either.

## Highlights

### Product — Templates

- **Publish a document as a template, start a new one from it** (#1000).
  The Canva / CapCut "Use template" loop over sheets, docs, slides,
  notes and boards. A template is **not** a `Document.type` — that
  column routes which editor opens a document — so the listing is a
  `TemplateListing` sidecar row keyed uniquely on `documentId`, and
  publishing is an upsert. It reuses `DocumentCopyService` rather than
  forking it: the service gained a `dest?: { workspaceId, folderId,
  title }` parameter defaulting to the source's, so existing
  `Make a copy` behavior is unchanged and every document type is covered
  by one engine.

  Two authorization rules carry the feature. Publishing is gated at the
  `isDocumentManager` tier at **every** visibility tier, the same bar as
  minting an editor share link and for the same reason — it hands the
  content to an audience workspace membership no longer bounds. And
  `POST /templates/:id/use` is the one route where a document crosses a
  workspace boundary, so authorization inverts: read authority from the
  listing's visibility, write authority from `assertMember` on the
  *destination*.

- **The gallery: listings become findable** (#1001). Phase 1 shipped one
  template, one link, one copy — nothing could find a listing you had
  not been sent. `GET /templates` is the collection every surface reads
  (the workspace **Templates** tab, the *New from template* picker, and
  later the public gallery), with three properties enforced in the
  service rather than in any caller: visibility is a **query
  constraint, never a post-filter**; no `scope` value selects `unlisted`
  listings, because holding the id is that tier's entire access story;
  and a card carries **no `previewToken`**, since a page of 24 would
  otherwise hand out 24 non-expiring read capabilities to render a grid.
  Paging is keyset on `(sort, id)`, not offset — a gallery ranked by a
  counter that changes under the reader would skip and repeat rows.

  Both Phase 1 shortcuts were cleared here. Preview embeds the real
  read-only viewer instead of opening `/shared/<token>` in a second tab,
  and a logged-out visitor returns to `/t/:id` after signing in — via a
  short-lived cookie re-validated by `safeReturnPath` on read, **not**
  via the OAuth `state`, which must stay an opaque token compared by
  equality.

- **Cards get a picture, and Phase 2's gaps close** (#1005). Capture is
  client-side at publish, because the renderers are all in the browser
  and the backend has no canvas: the mounted editor **registers a
  capture source** and the Share dialog asks a registry by document id,
  which is both the design (the dialog must not learn that a deck is
  painted differently from a spreadsheet) and what the frontend's
  architecture lint requires — `components/` may not import `@/app/*`.
  Slides render slide 1 offscreen so publishing from slide 7 still
  yields the deck's cover; `doc`, `sheet` and `board` composite the
  canvases already on screen, because neither package exports an
  offscreen renderer and a board has no first page at all; `note` — the
  one DOM editor with no canvas anywhere — is **synthesized** from the
  first lines of its markdown. `pdf` and `image` are not built yet.
  Every failure degrades to the type icon, never to a failed publish.

  It also closes three Phase 2 gaps: `sort=recent` was sorting the whole
  tier because the `useCount` index cannot serve `publishedAt` (there is
  now a matching index); publishing **and using** now refuse a document
  holding a `datasource`/`lakehouse` tab, since that tab references a
  workspace-scoped connection row and a copy elsewhere opens it empty;
  and the service, which had 26 unit tests against mocks and nothing
  through HTTP, gains an e2e suite covering what only a round trip
  shows.

  The `public` tier is still refused with a `400` until the Phase 3
  review pipeline exists. That is deliberate and is not a flag flip;
  the remaining phases stay tracked in
  `20260901-template-gallery-todo.md`.

### Product — Sheets

- **Client-side Parquet import** (#994, @lshtar13). The local half of
  the file-import plan's two-path split: `hyparquet` and its compression
  codecs decode the file in place, so a small `.parquet` becomes an
  editable sheet with no upload at all. The limits **move rather than
  being invented** — `createImportBudget` comes out of the CSV table
  writer, so both importers charge the same cell and document-byte
  budget and an over-budget file is refused instead of leaving a
  half-written sheet. A compressed file's size says nothing about how
  far it expands, so the upload queue's 50 MB cap cannot bound it: the
  footer's row × column count is checked in BigInt arithmetic before a
  single page is decoded.

  Values JavaScript cannot carry are kept literal (an INT64 becomes its
  digits, an unannotated BYTE_ARRAY becomes hex, a timestamp becomes a
  date cell), which required `toCell`'s `JSON.stringify` to stop
  throwing on a nested BigInt — a fix that **reaches every datasource
  read**, not only imports.

### CLI

- **Roughly 37 capability gaps close in the CLI layer alone** (#999).
  Every endpoint already existed; the CLI simply could not reach them.
  Added: `sheets styles` / `sheet-style` / `column-styles` /
  `row-styles` / `column-widths` / `row-heights` /
  `conditional-formats` / `data-validations` / `filter` / `pivot` /
  `freeze` / `hidden` / `merges` / `charts` / `clear` / `insert` /
  `delete` / `move`, `docs|slides|notes set-content`, and
  `images upload` / `get` / `delete`. All read their JSON body from
  stdin or `--data`, the way `sheets cells batch` already did.

### Collaboration

- **The document header stops jolting when presence loads** (#1003).
  Opening any document moved the Share button, comments toggle and sync
  chip 96 px to the right a moment after the page appeared: the presence
  slot reserved `w-32` while the Yorkie document attached, because
  `usePresences()` returns an empty list until `client.attach()`
  resolves, and the attached state is far narrower. Reserving exactly
  one avatar — the floor of the loaded state — makes the solo case,
  the common one, measure 0 px of movement.

  `docs/design/agentic-office-workflow.md`: an office-agent holding only

  Its capability audit was re-measured against `main` rather than

  Analytics were added to `app/Layout.tsx` only, so the seven other

  outside `Layout` — drifted, and opening a document showed a sidebar
  missing both entries. `useWorkspaceNavItems()` is now the only place
  the list exists, with a regression guard asserting no other file
  builds one. The eight call sites lose **233 lines net** between them
  (`git show --numstat`); the hook that replaces them is 77.

  #1002's own task doc says "Net −225 lines", which does not reproduce
