# Workspace Chat P1 (Chat page) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Chat page — public/private channels, DMs, threads, edit/delete, unread state and chat mentions in the bell — delivered in real time across backend replicas.

**Architecture:** A new NestJS `chat` module stores channels, members and messages in Postgres (Prisma), allocates a per-channel `seq` inside the insert transaction, and fans events out through Postgres `LISTEN/NOTIFY` to a per-replica hub that feeds a per-user SSE stream. The frontend adds a `/w/:workspaceId/chat/:channelId?` route inside `Layout`, React Query caches per channel, and a stream hook that appends or invalidates.

**Tech Stack:** NestJS 11, Prisma 6, `pg` (already a backend dependency), rxjs SSE, Jest (backend); React 19, React Query, Radix/shadcn, Vitest (frontend).

**Spec:** [`docs/design/chat.md`](../../design/chat.md) — P1 of § Rollout. P2 (document cards, editor panel, Send to chat) and P3 (bots, `/api/v1`, CLI, search) are out of scope here.

## Global Constraints

- Message body: plain text, trimmed non-empty, ≤ 4,000 characters; mentions as `@[username](userId)` (grammar from `@wafflebase/sheets`).
- Message page size: 50.
- DM member set: 2–8 people including the caller, all workspace members.
- Post throttle: 30 messages / 10 s per user (`UserThrottlerGuard`), on top of the global per-IP bucket.
- Stream: heartbeat every 25 s, `X-Accel-Buffering: no`, `@SkipThrottle()`.
- NOTIFY channel `chat`; payload carries ids only, never message content.
- `CHAT_LISTEN_DATABASE_URL` (optional) defaults to `DATABASE_URL`.
- A channel the caller cannot see is `404`, never `403`.
- `chat_thread_reply` is deduped per thread per hour; a DM or channel message reaches the bell only when it mentions the recipient.
- `seq` is a Postgres `BigInt`; serialize it to JSON as a `number`.
- ChatModule must not import `WorkspaceModule` (cycle — see `notification.module.ts`); membership checks go through Prisma.
- Repo artifacts in English. Commit subject ≤ 70 chars, body explains why, `pnpm verify:fast` green on every commit.

## Review Focus

1. **A member removed from the workspace while their stream is open** must stop receiving that workspace's events at once — Task 5 test `drops events for a channel after membership is revoked`.
2. **A client offline while messages were posted** (or a NOTIFY missed) must catch up on reconnect, not show a gap — Task 8 test `ready event refetches the open channel after its last seq`.
3. **Two people opening the same DM at the same moment** must land in one channel — Task 3 test `concurrent openDm calls return the same channel`.
4. **A deleted thread root** keeps its replies reachable and shows as deleted, not vanished — Task 4 test `deleting a root keeps the thread and blanks the body`.
5. **Posting to an archived channel** is refused (`409`) while reading still works — Task 4 test `archived channel refuses posts but serves reads`.

### Known limitations

- **Mention fan-out rate.** A chat post notifies up to 20 mentioned users
  (`MAX_RECIPIENTS`) at 30 posts / 10 s per user — up to 3,600 rows a minute
  into peers' inboxes, against the comment path's 30 reports × 20 recipients
  a minute. A per-recipient ceiling or a slower bucket for mention-bearing
  posts is the fix; deferred with the notification retention job.
- **Two primary Send buttons** when both the channel composer and an open
  thread's composer hold drafts.
- **No archive / rename / topic UI in P1.** The routes exist
  (`PATCH …/channels/:cid`); the Chat page exposes none of them yet.
