# Release v0.6.14 — Lessons

**Created**: 2026-11-08

- **Successful requests are not in the backend log.** Only errors and warnings
  are, so "no sign-in has happened since the rollout" and "sign-ins work" look
  the same. Verifying the login path after a rollout needs a person to sign in
  (or a request log at info level), not a log grep.
- **A rollout with `replicas: 1` and no readinessProbe probably drops
  in-flight sign-ins.** The one callback that failed arrived a minute after
  the new pod started, and its OAuth code exchange failed. The cause was not
  proven (a reused or expired code fits), but the timing points at the
  restart. Same structural gap the v0.6.13 lessons point at (a readinessProbe
  on `/health/ready`, in devops).
- **The ArgoCD sync can be triggered without the UI** by patching the
  Application's `operation` (`{"operation":{"sync":{"revision":"HEAD"}}}`).
