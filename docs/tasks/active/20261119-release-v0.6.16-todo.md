## Opening the public template gallery (after rollout, each step asked first)

The gallery's public tier refuses to open unless
`YORKIE_AUTH_WEBHOOK_ENFORCE=true` and `WAFFLEBASE_TEMPLATE_REVIEWER_IDS`
names somebody. Production has `ENFORCE=false` and no reviewer list, and
the public gallery is empty (`GET /templates?scope=public` → `[]`).

Setting `ENFORCE=true` alone would satisfy that check without enforcing
anything: the production backend logged **no** request to
`/internal/yorkie/auth` in seven days (only `/internal/yorkie/events`), so
the auth webhook is not registered on the Yorkie project. A public card's
preview token would then also be a write token to the template document.

- [ ] Register the auth webhook methods on the production Yorkie project
      (backend README → "Yorkie auth webhook"), keeping `ENFORCE=false`.
- [ ] Watch `[shadow] would deny` in the backend log for a few days; every
      one must be a correct refusal.
- [ ] devops: `YORKIE_AUTH_WEBHOOK_ENFORCE=true` and
      `WAFFLEBASE_TEMPLATE_REVIEWER_IDS=<maintainer's user id>`.
- [ ] `seed:templates` in the production pod into a templates workspace,
      then `register:templates` against wafflebase.io; 38 cards in the
      public gallery.
