# Release v0.6.11

**Created**: 2026-09-13

Cut `v0.6.11`. Two things, deliberately bundled: the fix for the image that
took production down on v0.6.10, and the bump to `@yorkie-js/sdk` 0.7.21.

## Why this release exists

v0.6.10 shipped a backend image that could not boot — `packages/slides/dist`
was never copied into the runtime stage, and #1022 had moved the backend's only
value import of slides into the Nest module graph, so a latent gap became a
crash loop. The Deployment reached `ready=0` with the previous ReplicaSet
already scaled to zero. Production was restored to v0.6.9 by
`kubectl rollout undo`, and `yorkie-team/devops#355` returned the manifest to
match.

So **production has been on v0.6.9 since**, and this release is what moves it
forward again. That is the reason the SDK bump rides along rather than waiting
for its own cut: there is one rollout to make, not two.

Full account: `20260913-wafflebase-v0610-image-incident-todo.md`.

## The box v0.6.10 is the reason for

- [ ] **Build the backend image and run `smoke-workspace-deps.cjs` against it
      before publishing.** Not after, not from CI's green tick alone.
      v0.6.10's `verify-backend-image` passed while the image could not start,
      because that job only ran the DuckDB extension smoke. #1063 added the
      workspace-dependency smoke to CI, and this box runs it locally too — the
      release is the last point where a broken image is still cheap.

## Why the SDK bump matters here

yorkie-js-sdk 0.7.21 fixes a client-wedging bug: `CRDTRoot.garbageCollect`
dereferenced a worklist entry without checking it resolved, and the throw lands
inside `Document.applyChangePack`, which every sync runs — so a client that hit
it never synced that document again. It also stops an ordinary `arr[i] = x` in
a loop from growing `docSize.live` without bound.

wafflebase is a heavy `arr[i] = x` consumer through the sheets grid, so the
unbounded-growth half is not theoretical here.

It pairs with yorkie 0.7.21 on the server, already rolled out to this cluster
(3/3 pods, 0 restarts).
