# Release v0.6.16 — Lessons

Todo: [20261119-release-v0.6.16-todo.md](./20261119-release-v0.6.16-todo.md)

## Lessons

- **Check the webhook is called before trusting `ENFORCE`.** The template
  gate reads `YORKIE_AUTH_WEBHOOK_ENFORCE` but cannot see whether the auth
  webhook is registered on the Yorkie project. Count
  `/internal/yorkie/auth` in the backend request log first: zero means the
  variable enforces nothing.
- **A Docker publish that fails on one architecture may be transient.**
  amd64 failed at `prisma generate` with no error text while arm64 passed on
  the same commit; `gh run rerun --failed` fixed it. Read the log before
  re-running, and re-run only once.
- **The `argocd` CLI here has no server configured.** Sync through
  `kubectl`: annotate `argocd.argoproj.io/refresh=normal`, then patch the
  Application's `operation.sync.revision` to the devops commit.
- **Shadow mode only covers the decision, not the guard in front of it.**
  `YorkieSignatureGuard` runs before `handleAuth`, so a request it rejects
  is a real `401` even with `ENFORCE=false`. Yorkie never signs auth webhook
  requests (yorkie#2416), so enabling the methods on production denied
  attaches immediately. Before registering a webhook on production, prove
  the round trip against a real Yorkie server; the e2e case for it is
  `it.skip` in CI, and unit tests only exercised the guard with signed
  requests.
- **The repo already knew.** `test/revision-history.e2e-spec.ts` (#1010,
  2026-09-03) recorded that Yorkie's auth webhook POST carries no
  `X-Signature-256` and bypassed the guard to get past it — inside an
  `it.skip` test. The README's production steps never mentioned it. A known
  environment gap belongs in the operator procedure, not only in a test
  comment.
