# Release v0.6.10

**Created**: 2026-09-13

Cut `v0.6.10` over the `v0.6.9..HEAD` window: 19 commits, 19 PRs, three
human authors plus the agent account.

## Why patch, not minor

The standing bar for a minor in this repo is a new document type or a new
workspace package. This window adds neither. Its largest items are a
`/api/v1` surface over capabilities the web editor already had (#1022), a
toolbar composed onto an existing route (#1046), and a pointer-media
re-gating of accommodations that already existed (#1031).

One item argues the other way and is worth naming rather than burying:
**#1046 flipped the Yorkie auth webhook's default from opt-in to
enforce-unless-`false`**
(`packages/backend/src/yorkie/yorkie-auth-enforcement.ts`, read by
`YorkieAuthController`'s constructor). That is a deployment-behavior
change, not a feature, and it needs an upgrade note rather than a version
bump — every affected deployment is one this repo's own devops manifest
pins.

## Release notes (the text to paste into the GitHub Release)

### Highlights

- **Notes on a share link is a real editor.** It was the only editable
  document type whose share route rendered the view and nothing else — no
  toolbar, no undo/redo, no formatting, no keymap picker, no image
  upload, and on a phone a fixed 50/50 split with no control that could
  leave it. (#1046)
- **Slides and board work with a fingertip.** The touch accommodations
  were gated on `useIsMobile()`, which answers "is this viewport narrow"
  — a different question from "is this driven by a fingertip", and one a
  tablet answers wrong. The axis becomes `(pointer: coarse)`. The board
  was not degraded but *unusable*: its three pan paths each need hardware
  touch cannot produce, and `touch-action: none` denied the browser its
  own pan on top of that. (#1031)
- **The docs word processor's editing rules got their model back.**
  Select-all-then-type is one undo unit instead of ~102 against a stack
  capped at 50 (past ~48 blocks the document's tail was unrecoverable);
  Clear formatting keeps hyperlinks, and the toolbar button and Cmd+\
  finally clear the same set; a list item's level change carries its
  nested children; inline highlights paint as one continuous band.
  Slides and Board mount the same text engine and inherit all of it.
  (#1047, #1052, #1053, #1040, #1042)
- **Comments, slides, tabs, sheet images and boards are reachable over
  the API.** Class B of the capability audit — the 18 items where no CLI
  command could close the gap because the capability lived only inside a
  Yorkie CRDT document and the backend had no route at all. Nothing here
  is a new product capability; what was missing was a way to do it
  without a browser. (#1022)
- **Any workspace member can mint their own API key.** Minting was gated
  on workspace ownership, which shut every non-owner out of the CLI and
  the v1 REST API while buying no privilege — a key already carries its
  creator's authority, re-checked on every request. (#1061)

### Security and deployment

- **The Yorkie auth webhook now enforces by default.**
  `YORKIE_AUTH_WEBHOOK_ENFORCE` used to have to be `true` before
  per-document access was enforced; it now enforces unless the value is
  `false` (`isYorkieAuthEnforced`, `packages/backend/src/yorkie/yorkie-auth-enforcement.ts:29`,
  read by `YorkieAuthController` at `yorkie-auth.controller.ts:158`). A
  typo therefore enforces rather than opening the door. Every server-side
  Yorkie client gained a scoped service token to keep working under it,
  and read-only mounts across sheets, docs, slides, board and pdf stop
  publishing presence, seeding roots, migrating and recalculating —
  because a refused write wedges that viewer's own sync. (#1046)
- **Upgrading does not switch it on for you.** Registering the
  auth-webhook methods on the Yorkie project is a project-admin step no
  environment variable can attest, and a deployment that sets
  `YORKIE_AUTH_WEBHOOK_ENFORCE=false` stays in shadow mode. Read the
  backend's boot line to find out which posture you are in — it says
  either `yorkie auth webhook: enforcing per-document access` or warns
  `SHADOW mode`. **Do not infer it from an absence of denials.**
- Docs correction shipped with this release: three pages described the
  off-switch as "the literal `false`, and only that". The code trims and
  lowercases (`raw?.trim().toLowerCase() !== 'false'`), so `FALSE` and
  ` false ` select shadow mode too. The docs now say so. No behavior
  changed; the description was wrong in the unsafe direction.

### Docs (word processor)

- Select-all then type is one undo unit, and so are cut, word/line
  delete, composition start, and the toolbar's block-style, list, indent,
  outdent, table-cell-style, insert-link and Replace All paths (#1047)
- Clear formatting keeps hyperlinks; `removeLink` stays the way to drop
  one, and Cmd+\ stops clearing a different key set than the button
  (#1052)
- A list item's level change carries its nested children, through one
  pure planner all seven writers route through (#1053)
- Inline highlights paint as one continuous band per line instead of
  per-word slivers separated by sub-pixel seams and justified gaps
  (#1040)
- Editing a link's URL updates display text that *was* the old URL;
  custom labels are left alone; a partial selection snaps out to the
  whole link (#1042)
- A page number in a header stops absorbing the text typed next to it
  (#1033)

### Slides / Board

- Touch input across the slides editor, presentation mode and the board
  (#1031)
- Resizing a rotated element from the Format options panel keeps it in
  place instead of throwing it across the slide (#1043)
- Miro import: Miro serialises every style number as a string
  (`borderWidth: "2.0"`) while the sibling geometry carries real numbers,
  so `num()` discarded the entire style layer; and `fillOpacity: "0.0"`
  is the norm on a real board while the mapper always wrote a solid fill,
  turning a transparent bordered rectangle into an opaque white box. The
  author measured both against a real 8,888-item board — 4,383 shapes had
  lost their outline and 7,242 of 8,888 items were transparent (#1032)

### Sheets

- Copy/cut/paste carries merged-block layout, drops fully-covered
  destination blocks, and refuses — visibly — a paste that would split a
  block or cross a freeze boundary. External TSV/HTML pastes deliberately
  keep their merge-blind behavior (#1059)
- A malformed A1 reference is a `400` naming it — on every cell verb that
  takes one in its path (`GET`/`PUT`/`DELETE .../cells/:sref`) and on
  every key of a `PATCH` batch — instead of a `500`. A malformed batch
  body is a `400` too, and a bare cell value (`{"A1": "Name"}`) is stored
  as the value instead of silently writing an empty cell (#1035)

### Sharing

- An editor-role share link can insert an image. It used to `401`, and
  `fetchWithAuth` read that as an expired session — so the visitor was
  logged out and redirected to `/login`, losing the only access they had
  (#1041)

### API / CLI

- Comments, granular slide ops, tab delete/reorder/duplicate, sheet
  floating images and board content over `/api/v1`, with matching CLI
  commands (#1022)
- Any workspace member can mint, list and revoke their own API keys;
  owners administer all of them, and a member naming somebody else's key
  gets `404` rather than `403` (#1061)

### Infrastructure

- `@yorkie-js/sdk` and `@yorkie-js/react` 0.7.20, for its duplicate-attach
  guard — the app mounts in StrictMode and every document route mounts a
  provider whose cleanup detaches asynchronously, so the window was
  reachable, and losing the client loses every document attached to it.
  0.7.20's offline local persistence is deliberately **not** adopted.
  Also fixes presence lost on re-attach (#1055)
- MinIO is pulled from quay.io: MinIO withdrew `minio/minio` from Docker
  Hub, so `verify-integration` failed before any test ran and a fresh
  `docker compose up` failed on any machine without cached layers. The
  quay.io image was verified to be the same build, not a lookalike
  (#1060)
- The review panel pages a human when a fix round is killed by its
  `timeout-minutes` wall, and the wall is 90 minutes (#1054)
- `@claude rerun` / `@claude loop` wait for an in-flight CI run instead of
  reporting "no CI run to re-run" and stalling (#1056)

## The outage

The v0.6.10 image could not boot:

```
Error: Cannot find module
'/app/packages/backend/node_modules/@wafflebase/slides/dist/node.cjs'
code: 'MODULE_NOT_FOUND'
```

The container exited 1 about two seconds in, five times. The Deployment reached
`ready=0` with the v0.6.9 ReplicaSet already scaled to zero, so **wafflebase had
no serving replica**. `replicas: 1` means there is no degraded state between
working and down.

`kubectl rollout undo deploy/wafflebase` restored v0.6.9 (ready, 0 restarts),
and `yorkie-team/devops#355` reverted the manifest so git matched the cluster —
the `wafflebase` ArgoCD Application has no `syncPolicy`, so nothing re-applied
it, but anyone pressing **Sync** would have re-broken it.

### Cause

The Dockerfile's runtime stage copies each workspace package's `dist/` **by
hand** and had no line for `slides`. It does copy every package's
`package.json`, so Node resolved the `exports` map and then failed on the file
it points at — which is why the error reads as a broken build rather than a
missing `COPY`.

The gap was **older than the failure**. The published v0.6.9 image has no
`packages/slides/dist` either (verified by running it), and it served for eight
days. It booted because the backend's only *value* import of slides was
`template/seed/builders.ts`, reachable from the seed command and not from the
Nest module graph. #1022 added `yorkie/slide-ops.ts` (`MemSlidesStore`), which
`api/v1/slides.controller.ts` pulls into that graph, so a latent gap became a
boot crash.

### Why CI did not catch it

`verify-backend-image` built the image and ran exactly one thing against it:
`smoke-duckdb-runtime.cjs`, which proves the DuckDB extensions are bundled. It
never resolved the backend's own module graph, so an image whose server could
not start passed — twice, on two architectures.

**I read that green check as "the image is verified" without reading what it
runs.** That is the whole defect in the release procedure, and it was one
`sed -n` on `ci.yml` away from being known.

### Fix

#1063: the missing `COPY`, plus `smoke-workspace-deps.cjs`, which `require`s
every `@wafflebase/*` dependency from inside the image and is wired into
`verify-backend-image`. It reads the dependency list from `package.json` rather
than hard-coding it, because the defect *was* a hand-maintained list nobody
extended — a hand-written list in the check would have had the same failure
mode. It also widened `.dockerignore` to `**/node_modules`, without which the
image could not be rebuilt locally at all, which is why nobody could have caught
this on a developer machine either.

Superseded by **v0.6.11**, which carries the fix and is what production runs
now. Full closure in `20260913-release-v0.6.11-todo.md`; the lessons are in
`20260913-release-v0.6.11-lessons.md`.
