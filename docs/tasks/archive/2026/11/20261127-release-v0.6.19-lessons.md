# Release v0.6.19 — lessons

- **The frontend shipped a whole release ahead of its backend.** Main auto-deploys to GitHub Pages while the backend image is pinned by hand, so by release day production already refused the template category filter (#1205) and 404ed webhooks, chat members and desktop sign-in. Cut the release soon after backend-facing PRs land, or gate the frontend on the backend version.
- **Merging into a known-broken window can be the right call.** The template filter had answered `400` on wafflebase.io since #1205, and waiting for green-everything only lengthened it. The maintainer chose an admin merge of #1208 and a same-hour backend pin, which closed the window instead of extending it.
- **A secret pasted at `gh secret set`'s prompt can carry whitespace.** The replacement `NPM_TOKEN` was valid locally yet `npm publish` answered `E404`, because the stored value had a trailing newline. Pipe it in trimmed (`pbpaste | tr -d '[:space:]' | gh secret set NPM_TOKEN`), and read an `E404` on publish as "auth" before "package".
- **A dev build and the release share the app's settings.** Both use the bundle id `io.wafflebase.desktop`, so `server.json` from local testing (`http://localhost:5173`) made the freshly downloaded release open on "You're offline". Verify a release on a machine (or account) that never ran a dev build, or give dev builds their own identifier.
- **Notarized is not "no dialog".** macOS still shows a one-time confirmation for any app downloaded from the Internet; notarization changes it to say Apple found no malicious software. Docs must describe that dialog rather than promise none.
