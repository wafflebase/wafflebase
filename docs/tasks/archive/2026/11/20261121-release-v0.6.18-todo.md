# Release v0.6.18

**Created**: 2026-11-21

Cut `v0.6.18` so the backend carries workspace chat (#1186). The frontend
already shipped it on merge (GitHub Pages deploys `main`), so until this
image is live the Chat page on wafflebase.io calls routes the `v0.6.17`
backend does not have — and every signed-in session opens `/chat/stream`,
which that backend answers `404`.

## Preconditions

- [x] **One Prisma migration, applied by the init container.**
      `20261121024348_chat` adds `ChatChannel`, `ChatChannelMember` and
      `ChatMessage`. `k8s/wafflebase/deployment.yaml` runs
      `prisma migrate deploy` in the `prisma-migrate` init container, so the
      rollout applies it before the server starts.
- [x] **One new, optional setting.** `CHAT_LISTEN_DATABASE_URL` falls back
      to `DATABASE_URL`. Production's `DATABASE_URL` points at the in-cluster
      `postgres:15` directly (no PgBouncer), so `LISTEN` round-trips and
      devops needs no new variable — only the image bump.
- [x] **New routes, frontend already ahead.** `/workspaces/:wid/chat/*` and
      `/chat/stream` (SSE, like `/notifications/stream`). No route was
      removed or changed, so the old frontend keeps working against the new
      backend.
