# Release v0.6.2 — Lessons

## Version-bump convention vs. maintainer call

The standing convention (documented in the v0.6.1 release todo) reserves a
**minor** bump for a window that adds a new document type, a new package,
or new infra. The `v0.6.1..HEAD` window added *both* a new `image` type
(#499) and a new `board` type + `@wafflebase/board` package (#606), which
by the letter of the rule reads as `0.7.0`.

The maintainer scoped it as a **patch (`0.6.2`)** anyway: `board` shipped
only as an SP1 canvas skeleton and `image` is a thin static-blob viewer
reusing the PDF spine — neither is a headline new surface. **Lesson:** the
convention is a default, not a gate. Surface the tension with the concrete
evidence (new `DocumentType` members, new package, user-creatable "New
Board" entry) and let the maintainer decide; record the override in the
release todo so the next release audit doesn't flag it as a mistake.

## Task-archive reconciliation is part of the release

The 49-task archive done just before this release is the release's
task-doc reconciliation step (same pattern as v0.6.1). Completed tasks
that shipped this window but left checkboxes unticked must be closed out
first, or `pnpm tasks:archive` (which only moves todos with zero unchecked
`- [ ]`) leaves them stranded in `active/`. Those working-tree changes
belong in the release PR, not a separate commit.

## target-version anomalies recur

Three design docs that shipped this window (`image-viewer.md`,
`workspace-folders.md`, `board/board.md`) carried `target-version: 0.7.0`
— written speculatively before the maintainer decided the bump. The
release prep must scan `docs/design/**` for target-versions that don't
match the release and correct the ones for features that actually landed.
Leave `template.md` (`X.X.X`) and genuinely-future docs alone.

## Mechanics

- 11 `package.json` files carry the version (root + 10 packages); internal
  deps use `workspace:*`/`workspace:^`, so no dependency-pin bump and no
  lockfile regen is needed for a version-only change.
- The only non-package `0.6.1` string in the tree after the bump is
  third-party `source-map@0.6.1` in `pnpm-lock.yaml` — unrelated.
