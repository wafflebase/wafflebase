# Release v0.6.6

Close out the v0.6.6 release covering the `v0.6.5..HEAD` window (40
commits, 7 authors). Theme: **the docs caret gets one authoritative home
for line affinity, notes grow real authoring controls, and reporting a
bug becomes a package you install rather than a screenshot you paste**.

**Patch (not minor) bump.** The window's largest addition is
`@wafflebase/debug-report` (#946), a new package — but the standing
convention reserves a minor for a **new document type** plus package,
and this ships no document type. Everything else extends surfaces that
already exist: notes toolbar controls, sheets merge propagation, a docs
caret refactor. Patch, consistent with v0.6.5.

## Highlights

### Sharing — the one to lead with

- **Workspace images are served to anonymous share-link viewers** (#955).
  Images embedded in a slides or board document are fetched over a plain
  image request carrying no Yorkie share credential, so the
  workspace-scoped image route answered 401/403 to anyone who was not a
  logged-in member — and the canvas painted `Image unavailable` in their
  place. **Every image in a shared deck was broken for the audience it
  was shared with.** Reported from a real incognito open of a shared
  deck.

### Product — Docs

- **The caret gets one home for its line affinity** (#943), and that
  affinity now resolves visual line boundaries (#931), rides selection
  endpoints (#930), and settles wrap behaviour inside table cells and
  header/footer regions (#942). Four PRs closing one long-standing class
  of wrapped-line cursor bugs.
- **Inline style toggled off clears the key** rather than storing `false`
  (#876) — the Google-Docs mismatch behind stale formatting flags.
- **Multi-block paste batches into one store write** (#940), so pasting
  costs one undo instead of many.
- A heading is restored when its list is removed (#862).

### Product — Notes

- **List controls and clickable preview checkboxes** (#925): bullet,
  numbered and checkbox toggles, indent/outdent, `[ ]` autoconversion,
  and task items that toggle from the rendered preview. Read-only shares
  stay read-only.
- **Quote, code and foldout buttons**, with foldouts flattened to read as
  ordinary text (#926).
- **Blame gutter** showing the author of each line (#924).
- Mermaid node labels render as SVG text rather than HTML (#928).

### Product — Sheets

- **Merged cells propagate through drag-move** (#927), and the cases the
  engine still refuses now say why instead of failing silently (#944).
- Borders clear by removing the key, not by storing `false` (#923) — the
  same shape of fix as the docs inline-style one.
- The decimal stepper steps from what the cell renders, not what it
  stores (#873).

### Product — Slides, Image viewer, Fonts

- The slides cursor heals when its slide leaves the deck (#911).
- **Back button and Esc leave the image viewer** (#922), returning to the
  document's own workspace list.
- **Font list previews load as their rows scroll into view** (#947) —
  previously every row pulled its family's CSS up front.

### CLI

- **The error envelope is attributed, and login is hardened** (#786).
- `--dry-run` is honoured in every command that still ignored it (#863).

### REST API v1

- **Worksheet settings** (#957): `freeze`, `hidden` and `merges` are
  readable and writable per tab. Landed with its input validation
  rewritten during the release review — merge keys now have to round-trip
  through the engine's own `parseRef`/`toSref`, spans and freeze counts
  are bounded by the grid, and hidden indices are 1-based like the A1
  refs the rest of the API speaks. Before that, one accepted request
  could leave a tab that threw for every collaborator on load,
  permanently.
- **Cell formatting** (#958): `style` can be written through
  `PUT`/`PATCH` on cells, whitelisted to the 15 `CellStyle` keys. It also
  repairs the read path — `GET` was returning the style **double-encoded
  as a JSON string**, because a Yorkie CRDT object serialises that way
  unless it is spread first.

### CI / build

- **The frontend vite config no longer needs Node to parse TypeScript**
  (#959). Vite externalizes bare specifiers, so importing
  `@wafflebase/debug-report/plugin` by name handed Node a `.ts` file —
  which only Node 22.18+ can read. Below that, `pnpm dev`,
  `frontend:test`, `frontend:build` and even `git push` (the pre-push
  hook runs `verify:self`) all died on a stack trace that never mentioned
  Node. CI could not catch it, because `node-version: 22.x` resolves to
  the newest 22; the guard added with the fix disables type stripping so
  a modern Node stands in for an old one.

### Developer tooling — debug-report (new package)

- **`@wafflebase/debug-report`** (#946): report a bug from the running
  screen — pick or region-select, one sentence, an agent drafts the issue
  text. Framework-agnostic core behind a `HostAdapter`.
- Capture reads what is on screen without destroying what it is
  reporting (#950), and the preview worker survives a child outliving its
  stdin (#952).
- **Shipped as a package any web app can install** (#954), which
  completes the stack — the reporter is no longer wafflebase-internal.
  Merged into this window on purpose so debug-report reads as one step in
  the notes rather than leaving a stray half in 0.6.7.
- **The repository half of the loop** (#961): intake routes each item to
  verify / appearance / duplicate / thin, verification emits lane
  commands, and PR assembly proposes the branch and body shapes. Nothing
  in it files, pushes or comments — every exit point writes JSON and
  stops, which is the design's stated Non-Goal held to. The only process
  it spawns is a read (`gh issue list`).

### Design editor (dev-only)

- A staged class edit is shown before it is written (#917).
- **A component previews on its own** rather than showing whichever route
  was last open (#960), plus fixes to the pipeline behind it. Its
  user-facing half is small but real: `/documents` could wedge in a
  microtask loop because an inline `folders = []` default made a fresh
  array every render.
- Note that #960 also **removes `"private": true`** from
  `@wafflebase/design-editor` and adds `publishConfig`/`files`/`prepack`.
  `npm-publish.yml` publishes only `@wafflebase/cli`, so this release
  pushes nothing new to npm — but a future `pnpm -r publish` would now
  publish this package, where before it was inert. Recorded here so it is
  a decision rather than an inherited default.

### Agent / review pipeline (dev infrastructure)

- A drained credential pool is classified as infrastructure, not as a
  finding (#953) — it was reading as ~4% spurious lens failures.
- `eval-replay` gained a `lenses_dir` input, checked before it spends
  (#951); `matchRebuttal` ties to the disputed finding rather than the
  whole rebuttal record (#949); lens ids are normalized where
  author-written records enter the panel (#948).
- Transient GitHub API errors retry in the agent workflows (#877), and
  `mark-ready.mjs`'s exit-code contract is pinned by a test (#929).

### Docs / tasks

- **Task archive**: 7 tasks archived (25 active → 18). Five were shipped
  with their boxes never ticked (#922, #925, #926, #927, #786). One
  (`docs-sync`) carried three "Still deferred" checkboxes that could
  never be ticked — converted to plain bullets, the convention v0.6.5
  established. Audited with six parallel agents, one per task group.
  The window then added three task docs back (this release, the Node
  floor fix, and #961's debug-report tracker), so `docs/tasks/active`
  ends at **21**.

## Found at cut time, and fixed in-window (#959)

#954 raised the minimum Node version silently. It was never a release
blocker — CI was green and the shipped artifacts were fine — but it
blocked local development on a supported Node, and nothing in the
repository said so.

`packages/frontend/vite.config.ts:10` now statically imports
`@wafflebase/debug-report/plugin`, and that package's `exports` map
points every subpath at **raw TypeScript** (`./src/plugin/index.ts`).
Vite's config bundler externalizes bare specifiers, so Node loads that
`.ts` file natively. That only works on **Node >= 22.18**, where type
stripping is on by default.

Confirmed rather than inferred, on Node v22.14.0:

```
node        -e "import('.../src/plugin/index.ts')"  -> ERR_UNKNOWN_FILE_EXTENSION
node --experimental-strip-types -e "same import"    -> OK
```

CI does not catch it because `setup-node` with `node-version: 22.x`
resolves to the newest 22 (v22.23.2 on the #954 merge_group run, where
`frontend:test` passed in 136s). `.nvmrc` says `22`, floating, and the
root `package.json` has **no `engines` field**, so a contributor on
22.14-22.17 — inside the active 22 LTS line — gets
`failed to load config from vite.config.ts` on `pnpm dev`,
`frontend:test` and `frontend:build`. It is a hard block at config load,
not a subtle bug.

The narrow fix would have been to state the floor (`.nvmrc` to a >= 22.18
version plus `engines.node`). #959 took the better one instead: stop
requiring Node to parse TypeScript at all. `/plugin` is the one subpath
Node loads directly rather than Vite transforming it, so it is the one
that should not be reached by a bare specifier. Importing it by relative
path makes esbuild inline it, and any Node 22 works again.

Two limits worth stating so nobody reads more into it. #959 fixes only
the frontend config: it adds no `engines.node`, does not pin `.nvmrc`,
and leaves `packages/design-sandbox`'s bare import of design-editor's raw
TypeScript alone — that dependency is pre-existing, dev-only, and
deliberately documented in its own `verify-tokens.mjs`. And CI still
cannot catch a *future* floor raise, because it tests only the newest 22;
pinning the matrix to the oldest supported version is left as a policy
decision rather than decided here.
