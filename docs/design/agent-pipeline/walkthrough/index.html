While presenting

  • Advance the deck with ← → or Space. Plain scrolling reads fine too.
  • Fullscreen the browser (F11) and it looks like slides. The current slide number sits in the bottom right.

Serving the pages

# From the repo root — just for yourself
python3 -m http.server 8080
→ http://localhost:8080/docs/design/agent-pipeline/walkthrough/

# When attendees need to open it over the same network
python3 -m http.server 8080 --bind 0.0.0.0
→ http://<my IP>:8080/docs/design/agent-pipeline/walkthrough/   (hostname -I gives you the IP)

Double-clicking the file to open it over file:// works as well.
A server is simply easier for sharing the link and for font caching.

Tell attendees this before the session

  • Node 22 or newer and git, plus git config user.name / user.email (they will be making commits)
  • Clone the repository — not a copy of it. Without an origin, the PR step goes nowhere.
  • Run pnpm design once before the session.
    The first install takes about 2 minutes, and on WSL2 the first scene load takes close to a minute.
    Getting it out of the way means nobody waits during the session.
  • Nothing to install for the editor — no pnpm, Docker or database. pnpm design prepares pnpm on a machine that does not have it, and the editor's scenes answer their own data requests from fixtures.
  • The GitHub CLI is only optional if you can push to origin. With push access, pnpm design-pr pushes the branch and opens GitHub's compare page in a browser. Without it, the branch has to live on a fork of your own and only gh can make one — so install it and run gh auth login before the session.
