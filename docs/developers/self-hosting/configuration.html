Configuration ​

Every environment variable a Wafflebase deployment reads, grouped by feature.

Conventions. Backend variables go in packages/backend/.env or the container environment and are read when the process starts. Frontend VITE_* variables are compiled into the bundle when you build it; setting them on the server that serves the files does nothing. The backend does not validate its configuration as a whole at boot. Only JWT_SECRET stops startup when missing; most other values fail when the feature that reads them first runs.

Backend: required ​

VariableRequiredDefaultWhat it does
DATABASE_URLYesnonePostgreSQL connection string
JWT_SECRETYesnoneSigns access tokens and Yorkie auth tokens, and refresh tokens unless JWT_REFRESH_SECRET is set. Missing, the backend exits with JWT_SECRET is required
GITHUB_CLIENT_IDYesnoneGitHub OAuth app client ID
GITHUB_CLIENT_SECRETYesnoneGitHub OAuth app client secret
GITHUB_CALLBACK_URLYesnonehttps://<backend>/auth/github/callback. Its scheme also decides whether cookies are Secure; see Serve sign-in over HTTPS
FRONTEND_URLYesnoneFrontend public origin. The CORS origin and the post-login redirect target

Backend: server and runtime ​

VariableRequiredDefaultWhat it does
PORTNo3000HTTP port
NODE_ENVNounset; production in the imageproduction removes the MinIO storage defaults and is the last fallback for Secure cookies
LOG_LEVELNoinfoPino log level
BACKEND_TRUST_PROXYNo0Number of proxy hops to trust for the client IP. Set 1 behind one TLS proxy
BACKEND_JSON_BODY_LIMITNo25mbRequest body limit for JSON, form, and text bodies. Raise it if large imports with inline images are rejected
WAFFLEBASE_API_ORIGINNoorigin of GITHUB_CALLBACK_URLThe backend's public origin. Used to recognize this deployment's own absolute image URLs when copying a document across workspaces. Set it to the same origin as VITE_BACKEND_API_URL

DANGER

Set BACKEND_TRUST_PROXY only when a proxy really is in front. At 0 behind a proxy, every request shares one rate-limit bucket. Above 0 with no proxy, clients can spoof X-Forwarded-For and evade rate limits.

Backend: blob storage ​

Two buckets with independent settings. Outside production each value falls back to the local MinIO container (http://localhost:9000, region us-east-1, keys minioadmin). With NODE_ENV=production there are no fallbacks. See Set up blob storage.

VariableRequiredDefaultWhat it does
FILE_STORAGE_ENDPOINTIn productionMinIOS3 endpoint for uploaded files, PDFs, and image documents
FILE_STORAGE_BUCKETIn productionwafflebase-filesBucket name
FILE_STORAGE_REGIONIn productionus-east-1Region
FILE_STORAGE_ACCESS_KEYIn productionminioadminAccess key
FILE_STORAGE_SECRET_KEYIn productionminioadminSecret key
FILE_STORAGE_PREFIXNoemptyObject-key prefix inside a shared bucket. Surrounding / are trimmed. Do not change it after the first upload
IMAGE_STORAGE_ENDPOINTIn productionMinIOS3 endpoint for images embedded in sheets, docs, slides, and boards
IMAGE_STORAGE_BUCKETIn productionwafflebase-imagesBucket name

Backend: datasources and lakehouse ​

Out-of-range integers are clamped to the nearest bound and non-integers keep the default; both log a warning at startup. An invalid memory limit falls back to 512MB without a warning.

VariableRequiredDefaultWhat it does
DATASOURCE_ENCRYPTION_KEYTo use datasourcesnone64 hex characters (openssl rand -hex 32). Encrypts stored database and lakehouse credentials. Changing it makes stored credentials unreadable
LAKEHOUSE_ALLOWED_ENDPOINTSNoemptyComma-separated exact HTTP(S) origins allowed as custom S3, Azure, or GCS endpoints and Iceberg REST catalogs. Empty allows none
LAKEHOUSE_QUERY_TIMEOUT_MSNo30000Query timeout, 100–300000
LAKEHOUSE_DUCKDB_MEMORY_LIMITNo512MBInteger followed by KB, MB, or GB
LAKEHOUSE_DUCKDB_THREADSNo21–32
LAKEHOUSE_DUCKDB_POOL_SIZENo21–8. Operations still run one at a time
LAKEHOUSE_DUCKDB_MAX_PENDINGNo64Queued operations, 1–1000
LAKEHOUSE_DUCKDB_EXTENSION_DIRNo~/.duckdb; /app/.duckdb-extensions in the imageWhere DuckDB loads extensions from
LAKEHOUSE_ALLOW_LOCAL_PATHSNofalsetrue lets lakehouse tables read the server's own filesystem
LAKEHOUSE_LOCAL_ROOTWith local pathsnoneThe only directory local paths may point into

Backend: share-link analytics ​

Set all three to turn analytics on. The Kafka brokers turn on recording views; the StarRocks DSN turns on the dashboards and the Analytics sidebar entry. Without the DSN, the dashboard says analytics is not enabled.

VariableRequiredDefaultWhat it does
WAFFLEBASE_KAFKA_ADDRESSESNononeComma-separated Kafka brokers for view events. Unset, no views are recorded
WAFFLEBASE_KAFKA_TOPICNowafflebase-view-eventsKafka topic for view events
WAFFLEBASE_STARROCKS_DSNNononeuser:pass@tcp(host:port)/db for the analytics warehouse. Unset, the dashboards are off

Backend: demo reset ​

Restores chosen documents to a pinned version once a day. Unset, no timer runs.

VariableRequiredDefaultWhat it does
WAFFLEBASE_DEMO_RESET_TARGETSNononeComma-separated <shareToken>:<revisionId> pairs. An entry without :<revisionId> is not reset; its recent versions with the label below are logged at startup so you can pick an ID. Editor share tokens are write credentials, so set this from a secret
